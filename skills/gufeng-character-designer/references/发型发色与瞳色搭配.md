# 发型、发色、瞳色与整套造型

## 发色与瞳色分开处理

发色和发型仍可按角色设定设计，特殊身份可询问是否希望尝试特别发色，并提供几组好看的选择。**瞳色不是默认设计项**，本条优先于旧模板或其他资料里“特殊身份主动提供瞳色”的做法。

- 用户没有提瞳色：保留普通自然眼睛，不另选颜色、不列色卡，不加入色环、发光、异瞳或其他特殊效果，也不主动问是否要特殊瞳色。人类、仙人、魔、妖、精灵、花仙都执行这一条。
- 用户主动说“帮我设计瞳色”时，可以给几组搭配选择；用户已指定颜色时直接采用，不要求重复确认。
- 用户主动提供美瞳图并明确要求使用其颜色时，按图分析并围绕该颜色重新设计人物；普通角色参考图上有异色眼睛，不构成采用该瞳色的授权。
- 用户要求特殊颜色不等于左右眼异瞳；语义会改变方案且无法判断时简短确认。

发色方案默认说明基色、挑染及位置、适合的衣物主辅色和配饰色。用户已主动要求瞳色时才额外列虹膜配色。不将未要求的瞳色偷偷并入整组搭配。

## 用户上传的美瞳或局部参考

以下段落仅在用户主动要求处理瞳色时启用。先实际看图，辨别虹膜主体色、瞳孔周围的内圈色、外缘色环、渐变与纹理，区分美瞳本色和照片灯光影响。用户说“瞳孔颜色”时，最终描述落实为虹膜色，瞳孔仍明确可辨；用户明确要特殊生理结构时另行遵从。

将看清的颜色特征写成可视化自然语言，例如“灰蓝色虹膜，靠近瞳孔处为浅金色细环，外缘是柔和的深灰蓝色环”，而不是只写“蓝眼睛”。看不清的纹理不编造，示例不作为所有角色的固定瞳色。

用户主动要求使用美瞳图颜色时，即使只有一张图和一句模糊气质，也仅将其明确指定的颜色作为已定项，设计其余五官、发型、发色、妆造、服装与配饰。当前参考优先，旧图库用于补充，不用旧库覆盖用户新图。

## 要求发型有设计感时

基于已定长相和身份，实际查发型专栏与综合库，尤其留意不常见的分区、盘编、束披、发束走势及色块分布。先设计发型本体，再决定是否用发色或挑染点睛，不把加一顶巨大头饰当作发型设计。

古风、现代、男女都允许挑染、局部色缕、内层染或发尾渐变。可根据人物提出粉发中的蓝色细缕、黑发中的蓝色挑染、白发中的粉色挑染等，也可以只染一缕；它们是允许的设计手段，不是每人必备的模板。不得因为“古风不能挑染”擅自排除。

选定后写清基色、彩色发束的位置、数量或范围、宽窄、起止与在束披结构中的走向。不要把“一缕蓝色挑染”写成全头蓝发，不在一条最终词里同时保留多组备选。

用户只要求造型或发型有设计感时，不自动重做已确认的脸。用户没有要求特殊发色时，也不为追求设计感强制加彩色挑染。

## 全套颜色联合设计

以用户已经确定的发色或衣服颜色为搭配起点；只有用户主动要求并确定了瞳色时，才把它也作为搭配起点，组织剩余部分。颜色可以相同、相近或形成对比，关键是整套协调好看、符合身份气质。

不要孤立选完一双特殊色眼睛，就随意补一套无关的衣服。一起检查具体色相、明度、饱和度、面积、面部周围的色彩重量，以及瞳色在衣服边饰、配件或内层中的呼应；不要求全身都用瞳色。

蓝色虹膜与紫色或红色衣服不是一概禁用，但不能仅凭色名就宣称相配。优先符合用户所给参考的搭配关系；色调、饱和度或大面积对比显得冲突时调整衣物主辅色、点缀面积或所选具体蓝色。给用户能一起判断的完整组合，而非互不关联的颜色清单。

好看仍是最高准则。选定后将发色与挑染、服装主辅色及配饰颜色同步编译到最终外观提示词；虹膜颜色与色层只在用户主动要求且已经选定时写入；未选择的方案不混入交付。
